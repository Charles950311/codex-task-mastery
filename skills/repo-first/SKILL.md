# Repo First（先搜后写，复用优先）

原则：**写代码是最后手段，不是第一反应。** 重复造轮子浪费时间和 token，还增加维护成本。

## 何时使用
- 要新增功能、工具函数、依赖、集成。
- 用户说“用现成的”“有没有现成的”“别造轮子”。
- 你正准备写一段“通用工具”代码。

## 预检（按需，只查与任务相关的渠道）
| 渠道 | 检查方式 | 缺失时 |
|---|---|---|
| 本仓库 | `rg` / `rg --files` 定向搜索 | 说明只检查了可见文件 |
| 已有技能 | `~/.codex/skills` 及项目本地 `.codex/skills` | 说明无本地技能目录 |
| 包管理器 | `npm` / `pip` / 项目自带包管理器 | 回退到网络 / 官方文档检索 |
| MCP | 可用工具列表 / 本地 MCP 配置 | 说明无 MCP 可用 |
| GitHub / 官方文档 | 检索维护良好的开源实现 | 说明检索渠道不可用 |

## 决策矩阵
| 信号 | 动作 |
|---|---|
| 精确匹配、维护良好、许可兼容 | **Adopt** — 直接采用 |
| 部分匹配、底子好 | **Extend** — 采用 + 写薄封装 |
| 多个弱匹配 | **Compose** — 组合 2-3 个小包 |
| 确实没有 | **Build** — 自研，但基于检索结论 |

## 红线
- 没查就写。
- 没查 MCP / 技能就宣布“没有”。
- 检索渠道不可用却装作查过——必须显式说明覆盖范围。
- 为一个小功能引入庞大依赖（依赖膨胀）。
- 封装过重，导致失去原库优势。
