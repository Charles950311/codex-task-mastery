# Plan Slices（切片与增量执行）

原则：**小步、可验证、可回滚。**

## 何时使用
- 任务跨多步骤 / 多文件，或改动有风险。
- 需要可评审、可回滚的增量交付。
- 需要先和用户对齐计划再动手。

## 流程

### 1. 先出轻量计划（30 秒的投资，省 30 分钟返工）
```
PLAN:
1. <切片> — <验证方式>
2. <切片> — <验证方式>
→ 若无异议即执行。
```
- 每个切片必须能**独立验证**。
- 切片粒度：一次聚焦的改动 + 一个检查。
- 动手前用几行把计划说出来，能在错误方向上少走很远。

### 2. 一次一片
- 每片：最小改动 -> 立即验证 -> 通过才进入下一片。
- 每片结束都处于干净状态（可提交、可回滚）。
- 失败或偏离计划：**停下**，说明偏离点，重规划后再继续。

### 3. 单一写入者（single canonical writer）
- 同一文件 / 同一工作流只由一条执行线改写，避免相互覆盖。
- 需要并行时，按**不相交的写入集**切分任务。

### 4. 依赖顺序
- 有依赖的按序推进；做下游动作前先确认前置已满足。
- 有依赖的任务串行，无依赖的可并行。

### 5. 复杂度最小化
- 先删除与复用，其次才是新增抽象。
- 能用 50 行解决，就不要 200 行。

## 红线
- 不一次改一大坨、最后才“一起测”。
- 不在计划里塞无法验证的步骤（那是伪进度）。
- 不因“顺手”扩大范围——这类改动会在 `verify-claim` 里暴露。
- 计划被新证据推翻时，先改计划，不要硬着头皮执行旧计划。

## 迷你案例
任务：给导出模块加 CSV 与 Excel 两种格式（约 5 个文件）。
动手前先出计划：
```
PLAN:
1. 抽出导出公共接口 + 单测（现有格式不回归）
2. CSV 实现 + 真实数据往返测试
3. Excel 实现 + 打开校验
→ 若无异议即执行。
```
一次一片：片 1 单测通过才进片 2；改坏现有格式 = 停下重规划，不带病前进。
错误示范：三片一起写完再"统一测"。
