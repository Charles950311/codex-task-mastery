# Prompt Forge（提示词生成与优化）

把“想法”变成“Codex 一看就懂、能高效执行”的提示词。

## 输出契约（先判断模式）
- **优化模式**（用户说“优化 / 帮我写 / 怎么写”）：只做顾问。**不执行任务、不改文件、不跑命令。** 产出 = 诊断 + 优化后的提示词 + 理由。
- **执行模式**（用户说“直接做 / 帮我实现”）：不要在优化模式里硬切实现；提示用户另行下单，或经确认后转入实现流程（`task-brief` → `plan-slices` → `verify-claim`）。

## 流程（6 步）

### 0. 探测项目上下文
读 `AGENTS.md` / `CLAUDE.md` 了解约定；从 `package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` / `pom.xml` / `Makefile` 等识别技术栈；识别本仓库可用技能（`~/.codex/skills` 及项目本地 `.codex/skills`）。都没有就标注“技术栈未知”。

### 1. 识别真实意图
归类：新功能 / 修 Bug / 重构 / 研究 / 测试 / 评审 / 文档 / 基建 / 设计。
区分**字面请求**与**真实目的**（用户说“做个后台”，未必真的需要后台）。

### 2. 评估规模
| 规模 | 判据 | 编排 |
|---|---|---|
| TRIVIAL | 单文件、< 50 行 | 直接执行 |
| LOW | 单组件 / 单模块 | 单技能 |
| MEDIUM | 多组件、同域 | 命令链 + 验证 |
| HIGH | 跨域、5+ 文件 | 先规划，再分阶段 |
| EPIC | 跨会话、跨 PR、架构级 | 需要多会话蓝图 |

### 3. 找缺口
逐项检查并列出缺失：目标 / 范围 / 约束 / 成功标准 / 环境 / 输出格式 / 交付物 / 已废弃路径。

### 4. 生成优化提示词
按结构化骨架产出（各任务类型模板见 `references/prompt-patterns.md`）：
```
【目标】一句可观察的结果
【背景】相关文件、约束、已有约定
【范围】要做 / 不做
【要求】技术栈、风格、边界条件
【完成标准】可验证的 Definition of Done
【输出格式】期望交付物形态
【验证】如何自证
```

### 5. 给出诊断与理由
- 原提示词的问题：歧义、缺验收、范围过大、无法验证、缺上下文、隐含假设……
- 每处改写一句话说明原因。
- 可选项：建议搭配的技能（如先 `task-brief` 对齐目的，再执行）。

### 6. 交付
输出**可直接粘贴运行**的最终提示词（放在代码块里），末尾一句“可直接使用；需要我继续执行吗？”

## 质量红线
- 不含可验证完成标准的提示词 = 不合格。
- 不为了凑格式编造上下文；未知就写 `TODO / 待确认`。
- 保持用户原意，只做补全与结构化，不擅自扩大范围。
- 不执行用户的任务（优化模式下）。

## 与其它技能的关系
- 目的本身不清 → 先 `task-brief`。
- 生成后要执行 → `plan-slices` 拆步，`verify-claim` 收口。
- 想省 token → `context-budget`。
