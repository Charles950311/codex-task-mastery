# Prompt 骨架与任务类型模板

> 供 `prompt-forge` 使用。选用与任务类型最接近的模板，再按需增删字段。

## 通用骨架（缺一不可的 4 项）
- **目标**：一句可观察的结果。
- **完成标准**：可验证的 Definition of Done（对应 task-brief 的验收标准）。
- **范围边界**：明确“不做什么”。
- **验证方式**：如何自证。

## 新功能 / 新项目
```
目标：实现 <功能>，使用户能够 <可观察结果>。
背景：技术栈 <...>；相关文件 <...>；已有约定 <...>。
范围：要做 <...>；不做 <...>。
要求：<接口/数据模型/边界条件/兼容性>。
完成标准：<AC-1>、<AC-2>；现有测试全部通过。
输出：<文件/接口/迁移脚本>。
验证：<测试命令>，附运行结果。
```

## 修 Bug
```
现象：<可复现步骤 + 实际结果>。
预期：<期望结果>。
环境：<版本/平台/复现频率>。
约束：先定位根因，不要只治表象；不顺手重构无关代码。
完成标准：<失败用例> 由失败转通过；不引入回归。
输出：根因说明 + 修复 + 新增回归测试。
验证：<测试命令> 输出为依据。
```

## 重构 / 简化
```
目标：在不改变外部行为的前提下 <重构目标>。
不变量：<必须保持不变的行为/接口/性能>。
范围：仅 <模块/文件>；不动 <...>。
完成标准：行为等价（现有测试全绿）+ <可量化改进，如复杂度/行数/耗时>。
输出：重构后代码 + 前后对比说明。
验证：<测试/基准>。
```

## 研究 / 方案对比
```
问题：<要回答的问题>。
范围：<技术栈/约束/时间>。
要求：给出 2-4 个方案，列 收益/代价/风险/适用条件；给推荐并说明理由；标注不确定来源。
完成标准：可据以决策；每条结论有来源或推理链。
输出：对比表 + 推荐 + 风险。
```

## 代码评审
```
对象：<PR/文件/变更范围>。
关注：正确性 / 边界条件 / 安全 / 性能 / 可维护性 / 一致性。
要求：按严重度分级；每条给出具体位置与可执行的修改建议；区分“必须改”与“可选”。
完成标准：无未分类的主要问题；结论可执行。
输出：按严重度分组的清单。
```

## 测试
```
目标：为 <模块/行为> 建立 <单元/集成/E2E> 测试。
覆盖：<正常路径 + 关键边界 + 失败路径>。
约束：用现有测试框架 <...>；测试要确定、可重复、不依赖网络。
完成标准：新增测试覆盖上述路径；<覆盖率阈值>；全量测试通过。
输出：测试文件 + 运行结果。
```

## 优化提示词的常见缺陷清单
| 缺陷 | 症状 | 修法 |
|---|---|---|
| 无验收标准 | 完成与否无法判定 | 加可验证 DoD |
| 范围过大 | 一次要求太多 | 拆成可独立验证的切片 |
| 缺上下文 | Agent 靠猜 | 补文件/约定/示例 |
| 隐含假设 | 结果跑偏 | 显式写出假设 |
| 不可验证措辞 | “更好/更快/更稳” | 换成数字或可观察证据 |
| 越权执行 | 让顾问模式改文件 | 明确“只说方案 / 直接执行” |
