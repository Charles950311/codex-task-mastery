# Token 估算与压缩指南

> 供 `context-budget` 使用。

## Token 粗估（启发式，约 85-90% 准确度，±15%）
- 纯散文：`词数 × 1.3`
- 代码密集 / 混合：`字符数 / 4`
- 混合内容按主导类型取启发式。

## 回复长度四档
| 档 | 目标长度 | 包含 | 省略 |
|---|---|---|---|
| 25% 精简 | 2-4 句 | 直接结论、关键判断 | 铺垫、举例、细则、备选 |
| 50% 适中 | 1-3 段 | 结论 + 必要背景 + 1 例 | 深度分析、边界情况、引用 |
| 75% 详细 | 结构化 | 多个例子、利弊、备选方案 | 极端边界、穷尽引用 |
| 100% 穷尽 | 不限 | 全部——完整分析、全部代码、所有视角 | 无 |

信号词映射：`1 / 25% / 短版 / brief / tldr`→25%；`2 / 50% / 适中 / 平衡`→50%；`3 / 75% / 详细 / 深入`→75%；`4 / 100% / 穷尽 / 全量`→100%。

## 压缩决策
**压缩时机**
- 研究 / 探索结束后、开始实现前
- 完成一个里程碑后、开始下一个前
- 调试结束后、继续功能开发前
- 放弃某方案后、尝试新方案前

**不要压缩**
- 实现中途（会丢失变量名、文件路径、部分状态）

**压缩时务必保留**
- 当前任务定义与验收标准
- 当前错误 / 失败信息
- 已确认的约束与决策
- 已修改文件清单（路径即可，不必贴内容）

## 上下文预算红线
- 同时启用的 MCP 建议 < 10 个；活跃工具 < 80 个。
- 每个任务的聚焦上下文目标 < 2,000 行。
- 到约 75% 就主动整理，不要等自动压缩（质量会在临界点陡降）。
- 长会话切任务时，考虑开新会话而不是硬撑同一上下文。

## 常见的浪费模式（避免）
| 模式 | 浪费点 | 替代 |
|---|---|---|
| 整仓库 / 整文件通读 | 大量无关 token | `rg` 定位后定点读 |
| 同一文件反复读 | 重复 token | 读一次，改后不重读 |
| 单条单条发工具调用 | 往返开销 | 独立调用合并批量 |
| 粘贴大文件给用户 | 输出 token | 引用文件路径 |
| 顺着引用无限深挖 | 无关上下文 | 只读当前任务需要的 |
| 全程 100% 详答 | 输出 token | 按需分档 |
